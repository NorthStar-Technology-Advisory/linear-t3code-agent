# Install the Linear ↔ T3Code bridge

This guide adapts the upstream service deliverable. Choose your own hosting and process supervisor. Provision a dedicated account for the bridge and T3Code with only intended repository credentials and integrations. Delegation grants full coding and draft-PR permissions; project allowlists and worktrees do not confine filesystem access.

1. Install Node.js 22.13 or newer, npm, git and GitHub CLI. Authenticate `gh` as the service account. Configure git commit identity. Clone intended repositories and verify the account can create worktrees and push branches.
2. Run T3Code on localhost or a private network. Configure its providers/models and create a T3Code project for each repository. Record each project's ID and actual workspace root. Obtain a server-side bearer credential granting `orchestration:read` and `orchestration:operate` using T3Code's current [environment authentication](https://github.com/pingdotgg/t3code/blob/main/docs/internals/environment-auth.md) flow. Store credentials only in the private service environment; do not put them in Linear issues or public URLs.
3. Clone this service separately from target application repositories. Run `npm ci`, copy `.env.example` to `.env`, and fill in the Linear credentials, T3Code connection, provider instance/model and explicit `PROJECT_ROUTES`. The paths must refer to the same files for both processes. Use local durable storage for `BRIDGE_DB_PATH` and `WORKTREE_ROOT`.
4. Create a Linear OAuth app, using your public HTTPS URL plus `/linear/oauth/callback` as the redirect URI and `/linear/webhook` as the webhook URL. Enable Agent Session events. The installation uses `read`, `write`, `app:assignable`, and `app:mentionable` scopes. Set the app's webhook secret in `LINEAR_WEBHOOK_SECRET`. Configure a random `INSTALL_SECRET` of at least 16 characters before exposing the install route.
5. Run `npm run typecheck` and `npm run build`, then `npm start`. Forward only the required bridge endpoints through your HTTPS proxy. Verify `/healthz`, then run `npm run smoke:webhook` to check signing and freshness. These checks do not start coding work.
6. Open `/linear/install?install_secret=...` privately and complete OAuth. Avoid retaining the secret-bearing URL in proxy logs. An Authorization Bearer header is also accepted by the install endpoint. The access and refresh tokens are stored in `TOKEN_STORE_PATH` with private permissions.
7. Delegate a disposable representative issue in a mapped project. Verify its isolated thread/worktree, draft PR and validation report. Send a follow-up and verify the same PR updates. Restart the bridge during work and verify recovery. Stop an active session from Linear and verify edits survive and queued prompts are cleared. Exercise a question and an explicit approval. Record results using [docs/acceptance/nor-173.md](docs/acceptance/nor-173.md) before calling the deployment ready.

For user-systemd, adapt `systemd/linear-t3code-agent.service.template` to the installed paths and Node binary, copy it to your user unit directory, and enable it with your normal service-management process. Other supervisors can invoke `node dist/server.js` from the service directory with the same environment. No Pi executable or Pi SDK is required.

For upgrades: stop the bridge, take a consistent state/context backup, install/build the update, and restart against the same database. Do not reset the database or move worktrees to work around an integration error. The bridge reports authentication and contract failures; repair the adapter or credentials while preserving session identity. Only one process may own a database. A stale ownership record is recovered when its previous PID no longer exists; if that PID was reused by an unrelated process, stop and reconcile ownership manually rather than deleting the state database.
