Validated 2026-09-14 against the configured local T3Code v0.0.40 at `http://127.0.0.1:3773` and its installed source maps. Temporary bearer credentials were issued through `t3 auth session issue`; no credentials are recorded here.

## Live API evidence

- The production adapter read active project identity/title/workspace and resolved the existing bridge project to `codex / gpt-6-astra`, `worktree`, and start-from-origin enabled using authenticated `server.getSettings` and `server.getConfig` RPCs. Null project overrides inherited environment defaults.
- `vcs.listRefs` resolved a disposable repository's default branch to `main`.
- The first disposable probe established that **HTTP dispatch accepts but does not execute bootstrap preparation** in this installed build. Installed source confirmed that HTTP dispatch calls the orchestration engine directly; `orchestration.dispatchCommand` runs the bootstrap handler. The adapter now uses that WebSocket RPC for bootstrap, and the fake service reproduces the HTTP distinction.
- Corrected probe thread `e2c6672f-8f3e-47c3-82ee-68c90c19f6af`, project `3e1f2a1f-822b-4a9a-8b7f-eb56136cb590`, completed successfully through the production adapter. The new worktree's HEAD matched a newer commit in a disposable origin repository, while the original checkout remained at its previous HEAD. The configured T3Code setup script wrote its expected `ready` marker; the snapshot contained `setup-script.requested` and `setup-script.started` activities. The provider was asked only to return a probe acknowledgement and not to use tools or modify files.
- Setup scripts are the scripts configured in T3Code. A `t3.json` script entry alone was not imported into the project by this probe; the successful setup probe configured its script through `project.meta.update`.
- T3Code's original workspace path spelling is retained for worktree bootstrap because setup lookup uses that path. Canonical paths are used for current-checkout reservations and worktree identity checks.

## Automated coverage

The signed-webhook integration suite uses fake Linear and T3Code services, real temporary Git repositories and real SQLite. It covers exact active-title matching and routing corrections, inherited/overridden/unavailable models, workspace precedence, default and checked-out branch selection, bootstrap recovery, concurrent canonical-checkout claims, reservation retention, delayed stop and terminal local cancellation, PR closure, file preservation, session identity and duplicate/restart recovery. Configuration tests cover startup without UUID routes or bridge model defaults, connection validation and redaction.

Live validation here establishes the configured T3Code settings and worktree contracts. Linear label routing and checkout reservation lifecycle were exercised through the signed integration harness, not through a new live Linear delegation. The original broader delegation/PR acceptance remains in [NOR-173](nor-173.md).

All 73 automated tests, typechecking and the production build passed. Disposable probe providers were stopped, their threads/projects deleted, and their temporary repositories/worktrees removed.

Review added regressions for a connection loss between worktree metadata and setup/turn submission, and cancellation when workspace files are unavailable. Unconfirmed bootstrap setup now pauses for operator repair followed by explicit `resume`; cancellation reaches provider stop before attempting workspace validation.
