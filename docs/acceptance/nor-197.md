## Remaining live acceptance

Use disposable issues and a repository intended for acceptance work. An operator must configure marked statuses and subscribe the installed app to Issue updates; humans must review results and request stage progression.

1. Delegate the disposable parent in a status marked `t3code: grill-me`. Verify an actual delegation webhook, installed skill invocation, a correlated question, an answer in Linear, and parent Q&A comments.
2. Have a human move it to `t3code: to-spec`. Verify an actual Issue update event, the preserved planning thread and a reviewable parent specification.
3. Have a human review and move it to `t3code: to-tickets`. Complete skill-required review. Verify native children, acceptance criteria, source links and blocking dependencies; children must remain undelegated.
4. Delegate one child in `t3code: implement`. Verify a fresh thread with explicit parent/ticket handoff and normal validation/draft-PR delivery. Follow up and confirm the same implementation thread/PR.
5. During a running stage or unanswered question, move the parent to another status. Verify provider stop before replacement work, inactive old questions, preserved files and current-state recheck after rapid moves.
6. Restart during a transition and during a pending artifact acknowledgement. Verify retained identities and no duplicate turn, comment, child or dependency.
7. Re-enter planning. Verify its original conversation, updated unstarted children, and review notes instead of changes to active/completed children. Test direct parent implementation and return to planning with preserved Git/PR state.

Do not report the full live acceptance exercise as passed until these observations are recorded. No production statuses, delegation or running services were changed by the read-only probe.
